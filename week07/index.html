第七週｜期中提案 · 形式不限01 / 08

PURPOSE

先說清楚問題，
再介紹你想做的專題。

使用者與情境

誰會使用？在什麼情境遇到困難？為什麼值得改善？

提案與價值

你打算提供什麼服務？使用前後會有什麼不同？

可以提出尚未實作的構想；不要求已完成網站、程式或資料庫串接。

重點是讓別人理解提案，不以功能完成度代替說明02 / 08

PROPOSAL FLOW

提案照這五步說明。

  1. 問題與使用者：用一個具體情境開場。
  2. 解決構想：介紹專題想提供的服務與價值。
  3. 使用情境：用選擇的形式說明使用者會如何使用。
  4. 執行計畫：先做哪些功能、如何分工與安排進度？
  5. 待確認事項：有哪些疑問、限制或需要協助的地方？

每組時間、順序、期限與繳交平台，依老師課堂公告。

用任何形式提出期末專題的提案計畫03 / 08

ANY FORMAT

形式由你決定，
讓構想容易被理解。

可以說、畫或演

簡報、海報、手繪草圖、故事板、角色扮演、影片，或其他你想到的形式。

也可以做原型

紙上原型、畫面模型、互動原型或程式展示皆可；已有作品可輔助說明。

不必準備可操作網站或輸入驗證測試。使用模型或影片時，說清楚哪些是構想、哪些已實作。

形式不限；共同目標是說明問題、提案與計畫04 / 08

PLAN

把想法拆成，
接下來能做的幾件事。

先做什麼

挑出期末想完成的核心功能，列出先後順序；進階想法可以留作延伸。

誰來做、怎麼確認

說明各組員預計分工、重要進度，以及如何知道作品能幫上使用者。

若使用 AI 或外部素材，說明用途、來源與自己如何理解及查證。可以提出不確定的技術問題請老師協助。

不要求現場修改程式；請能說明自己的提案內容05 / 08

READY TO PRESENT

提案前，
確認這些內容說得清楚。

提案計畫大綱提案檢核與回饋表
沿用期中報告占 25%；不新增評分比例06 / 08

PEER FEEDBACK

幫同學把提案，
說得更清楚、更可行。

  1. 我理解你想幫助的使用者是＿＿，要解決的問題是＿＿。
  2. 我最想進一步了解的是＿＿。
  3. 我建議先完成＿＿，因為＿＿。

針對提案的情境、價值與可行性提供具體建議；報告後選一項回饋修訂計畫。
