第九週教師指南｜表單接上資料庫

120 分鐘，含 5 分鐘短休息。沿用第六週表單與第八週 SQL 基礎，主課只做新增、查詢與驗收。

課前 Windows 試跑

  1. 用上課帳號在 SSMS 連 localhost\SQLEXPRESS，確認能建立練習資料庫；不需要改 Lab08。
  2. 在學生工作副本跑 Starter，驗證空欄和 Email 錯誤；再依三段覆蓋；每次先停網站，複製後 dotnet clean，再 build／run。預先還原套件與工具。
  3. 確認兩個 EF Core 套件和本機工具都是 10.0.15。準備離線檔案不代表 NuGet 已快取；課前先 restore。
  4. 由尚無 Lab09 的環境開始試跑。若 Lab09 已存在，先核對原專案的 MigrationId 與 __EFMigrationsHistory；只有同一套歷史才 update，不清除學生資料。
  5. 依 SSMS、POST 保存、GET 清單、無效 POST 不增筆、重新整理、重啟後資料仍在等項目完成真實試跑。

三個共同停點

60 分鐘：資料庫

Lab09 有五欄與 Migration 歷史，SSMS SELECT 正常。落後者保留原專案與 Migrations，依序套用後續 Checkpoints。

85 分鐘：保存

合法資料 +1；五欄相符；保存後為 GET。不要以摘要當保存證據。

105 分鐘：清單

最近 10 筆順序正確；無效輸入仍顯示舊清單；不新增。

120 分鐘：驗收

關閉網站再啟動，Id 仍在；學生說出 Input、Entity、Context 的工作。

常見錯誤與處理

找不到專案／dotnet 指令：先 Get-ChildItem *.csproj；確認 .NET 10 SDK 安裝完成，重開終端機。

dotnet ef 找不到／版本不同：在工作專案根目錄 dotnet tool restore；確認 .config/dotnet-tools.json 被複製，工具固定 10.0.15。

編譯找不到 DbContext／UseSqlServer：核對 csproj 的 SqlServer／Design 套件、using 與 Week09Lab namespace，先 dotnet restore、dotnet build。

連線逾時／登入或憑證錯誤：先用同一 Windows 帳號在 SSMS 連同一執行個體；確認服務、帳號權限及本機憑證設定。

Invalid object name／資料表不存在：確認 Lab09、database update 已成功、Tables Refresh；不能只做 migrations add。

Migration 同名／物件已存在：保留原工作專案與 Migrations，使用 Checkpoints 接回進度。Complete 與自行產生的 InitialCreate 編號不同，不可混用；不刪表、不改 Migration 歷史，請教師核對。

送出成功卻查不到／查到舊資料：核對正在跑的專案、埠號、連線字串及 SSMS 伺服器；資料夾若有兩份，不要同時跑。

已有清單在驗證失敗後消失：無效 POST 分支先 await LoadRegistrationsAsync() 再 return Page()。

接回進度：先保留 Migration 歷史

工作專案與資料庫是一組。自行產生的 InitialCreate 與 Complete 的時間戳不同；EF Core 會按完整 MigrationId 判斷是否已套用。已完成步驟 5 的同學，保留自己的 Migrations 與 appsettings.json，只套用後續 Pages 檔。

教師在工作專案執行 dotnet ef migrations list --no-connect，再用 SSMS 查下方歷史，比對完整編號。若不一致，先找回原工作專案；不要以刪表或修改歷史當作一般解法。

USE CampusActivityLab09;
GO
SELECT MigrationId, ProductVersion
FROM dbo.__EFMigrationsHistory
ORDER BY MigrationId;

替換檔案後仍顯示舊畫面：先 Ctrl+C 停止網站，在工作專案執行 dotnet clean，再 dotnet run --launch-profile http。複製檔案可能保留舊時間戳；clean 會清除舊編譯結果，不刪 Migrations 或資料庫。

節奏與救援

時間不足時，略過手打完整類別，以提供的分段檔閱讀並驗收；不要省略最後 15 分鐘的實作，也不要加講修改、刪除、Repository 或關聯表。不要同時跑 Starter 與 Complete：兩者預設同一個 5090 埠。

驗證範圍

教材程式會做編譯、Migration SQL 產生與獨立自動化流程檢查；Windows 驗證、SQL Server 服務與權限仍須教師依本頁在教室實測。自動化測試使用的 SQLite 測試環境不是學生使用的 SQL Server 設定。
