第九週｜EF Core 表單存取指南

2 小時，從第六週的表單接到 SQL Server。每次只完成一段，核對結果再往下。

下載學生包操作指南 PDF第九週簡報

本週目標

驗證失敗不寫入；合法表單新增一列；網頁查回最近 10 筆；關閉網站後資料仍在。

課前環境

Windows、.NET 10 SDK、SQL Server Express、SSMS；第八週 localhost\SQLEXPRESS 連線成功。

本週使用新資料庫 CampusActivityLab09。第八週 CampusActivityLab08 仍保留；不要對它執行 Migration。本週延續第六週的場次「週三晚上／週六下午」，不使用第八週的上午場示例。

學生包怎麼用

  1. Starter：可啟動的第六週表單起點。先複製成自己的 Week09Lab 工作資料夾。
  2. Checkpoints：三段替換檔，依順序複製「裡面的內容」到工作專案；不直接執行此資料夾。每次複製前 Ctrl+C 停止網站。
  3. Complete：含 Migration 的完成版，供接回進度與課後比對；不要與 Starter 同時執行。
  4. verify-in-ssms.sql 在 SSMS 執行；dotnet 指令在 .csproj 所在目錄的 PowerShell 執行。首次還原 NuGet 與工具需要網路。

課堂只用假姓名與 example.com Email；這是練習專案，資料清單未做登入保護，不部署成公開報名服務。

1. 先讓第六週表單跑起來

  1. 下載並解壓學生包，保留 Starter、Checkpoints、Complete 三個資料夾。另複製 Starter 為自己的 Week09Lab 工作資料夾。
  2. 用 Visual Studio 開啟 Week09Lab.csproj。開啟「檢視 → 終端機」的 PowerShell；用 Get-ChildItem *.csproj 確認目前目錄就是 Week09Lab.csproj 所在位置。不要把指令貼到 SSMS 或 C# 檔。
  3. 執行下方指令；瀏覽器開啟終端機顯示的網址（預設 http://localhost:5090）。
  4. 先送出空表單，再送出小安／xiaoan@example.com／週三晚上。這一段只顯示摘要，還沒有存進 SQL Server。
dotnet --version
dotnet run --launch-profile http

課前先裝好 .NET 10 SDK、SQL Server Express、SSMS。SDK 輸出應為 10.0.x；已確認的範例套件與 dotnet-ef 固定 10.0.15，不跟隨升到 11.x。若 5090 被使用，先停止舊網站。

2. 套用第一段：認識六個檔案

  1. 在終端機按 Ctrl+C 停止網站，確認沒有另一份同名專案仍在執行。
  2. 將 Checkpoints/01-Database 裡的檔案與資料夾複製到自己的 Week09Lab 根目錄，保留層級並取代同名檔；包含 .config/dotnet-tools.json。不要把整個 01-Database 外層資料夾放進去。
  3. 逐一打開 Models/Registration.cs、Data/CampusActivityContext.cs、Program.cs、appsettings.json、Week09Lab.csproj、.config/dotnet-tools.json。
  4. 閱讀後執行下方指令。還原套件需要網路；請等每個指令完成才繼續。
dotnet restore
dotnet tool restore
dotnet ef --version
dotnet build

複製檔案是接回進度的方式：先看懂改了哪裡，再執行。不同專案的 namespace 不可直接混貼。套件：SqlServer 提供 SQL Server 存取；Design 配合 Migration；工具在本專案用 dotnet tool restore 還原。

3. Entity 與 Context：一筆資料和一張表

RegistrationInput

保留第六週四個欄位與驗證規則；接收瀏覽器輸入，不讓使用者指定 Id。

Registration

加上資料庫主鍵 Id，形成五個欄位；Email／Note 也會保存。

public int Id { get; set; }
[Required, StringLength(20)]
public string DisplayName { get; set; } = string.Empty;
[Required, StringLength(254)]
public string Email { get; set; } = string.Empty;
[Required, StringLength(20)]
public string Session { get; set; } = string.Empty;
[StringLength(100)]
public string? Note { get; set; }

這是 Registration 類別內的屬性節錄；完整檔案已在 Models/Registration.cs。DbSet<Registration> Registrations 對應報名集合；Context 讓 EF Core 讀寫資料庫。

public DbSet<Registration> Registrations => Set<Registration>();

4. 連線：由 Program.cs 把 Context 接起來

builder.Services.AddRazorPages();
builder.Services.AddDbContext<CampusActivityContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("CampusActivity")));

以上是 Program.cs 的服務註冊節錄。建構式收到的 Context 由 ASP.NET 建立；這一週先認得這個用法，不必背完整相依性注入原理。

"CampusActivity": "Server=localhost\\SQLEXPRESS;Database=CampusActivityLab09;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True"
  1. 上方連線字串是 appsettings.json 的 ConnectionStrings 內一行。檔案已提供完整 JSON，不要把這一行單獨覆蓋整份檔案。
  2. Server 使用第八週連線成功的執行個體；JSON 的反斜線要寫兩個。SSMS 輸入名稱時只寫一個。
  3. 確認 Database=CampusActivityLab09。不要改為 CampusActivityLab08 或原延伸教材的 CampusActivityDb。
  4. Trusted_Connection 使用執行網站的 Windows 帳號；本機課堂 TrustServerCertificate=True 僅供已核對目的地的練習環境。

如果 SQL Server 服務未啟動、帳號沒有建立資料庫權限，請先處理環境，不要先改 C#。

5. Migration：先產生變更，再套用到 SQL Server

  1. 此步使用自己的 Starter 工作副本，已完成第一段且沒有 Migrations 資料夾。仍在 .csproj 所在目錄操作。
  2. 依序執行下方兩個指令。第一個產生 C# 變更檔；第二個才連到 SQL Server 建庫／建表。
  3. 若已做過第一個指令，或正使用 Complete 完成版，不要再加同名 Migration，直接執行 database update。
  4. 不要在 SSMS 手動 CREATE TABLE，也不要使用 EnsureCreated；本週交給 Migration 管理新資料庫。
dotnet ef migrations add InitialCreate
dotnet ef database update

第一個指令成功不等於資料表已存在。第二個成功時通常顯示 Done；沒有待套用變更也可能顯示資料庫已是最新。遇到同名物件錯誤先核對目的地與 Migration 歷史，不刪學生資料。

6. 第一個停點：用 SSMS 核對五個欄位

  1. 沿用第八週 Windows Authentication 連線。右鍵 Databases → Refresh，展開 CampusActivityLab09 → Tables。
  2. 確認 dbo.Registrations 的 Columns 有五欄；Id 是 int 主鍵與自動編號，其餘文字欄位長度與 Registration 相同。
  3. 會另外看到 __EFMigrationsHistory；這是 EF Core 的變更紀錄，不是學生報名表。
  4. 在 SSMS 新查詢執行 verify-in-ssms.sql；記下目前筆數。尚未新增時為 0；沿用舊練習資料時不一定為 0。
USE CampusActivityLab09;
GO
SELECT DB_NAME() AS CurrentDatabase;
SELECT COUNT(*) AS TotalCount FROM dbo.Registrations;
SELECT TOP (10) Id, DisplayName, Email, Session, Note
FROM dbo.Registrations
ORDER BY Id DESC;

到這裡先停下核對，再休息 5 分鐘。若不見資料庫，回到 database update 的第一個錯誤，不要直接跳到送表單。

7. 第二段：驗證通過後新增一筆

  1. 保持網站停止，將 Checkpoints/02-Save/Pages 的兩個檔案複製到工作專案 Pages，取代 Index.cshtml 與 Index.cshtml.cs。
  2. 查看 OnPostAsync：ModelState 無效就 return Page()；有效才建立 Registration。下方是保存部分。
  3. 執行 dotnet run --launch-profile http。輸入小安／xiaoan@example.com／週三晚上／第一次 EF Core 練習，只送出一次。
  4. 此段先不顯示清單。看到保存編號後，到 SSMS 重跑 verify-in-ssms.sql，比對五欄與筆數。
var registration = new Registration
{
    DisplayName = Input.DisplayName,
    Email = Input.Email,
    Session = Input.Session,
    Note = Input.Note
};
_db.Registrations.Add(registration);
await _db.SaveChangesAsync();

Add 只是把新增工作交給 Context；await SaveChangesAsync 才寫入。只有成功後才顯示編號並 RedirectToPage。請勿把整段節錄加在原本 OnPost 旁邊造成兩個 handler。

8. 第三段：GET 查回清單，Razor 顯示資料

  1. 停止網站，將 Checkpoints/03-Query/Pages 的兩個檔案複製到工作專案 Pages，取代同名檔。
  2. OnGetAsync 呼叫 LoadRegistrationsAsync。下方查詢取得最近 10 筆，並交給 Registrations 屬性。
  3. 在 Index.cshtml 找到 foreach；它把每筆資料輸出到清單，空集合則顯示「目前沒有報名資料」。
  4. 重新啟動網站；應看到剛才那筆資料。先前沒有資料則先新增一筆再查。
Registrations = await _db.Registrations
    .AsNoTracking()
    .OrderByDescending(item => item.Id)
    .Take(10)
    .ToListAsync();
@foreach (var item in Model.Registrations)
{
    <li>
        #@item.Id · @item.DisplayName
        <p>@item.Email · @item.Session</p>
    </li>
}

ToListAsync 執行查詢；OrderByDescending 決定順序；Take(10) 限制顯示筆數。它們不會刪掉舊資料，SSMS 的總筆數可能比網站多。

9. 保留第六週驗證，再檢查重新整理

  1. 先確認清單已有合法紀錄，再送出空姓名／空 Email／空場次；應顯示錯誤而不新增。
  2. Email 改成 abc 再送出；應顯示格式錯誤。程式也限制 Email 254 字與允許的場次值。
  3. 注意無效 POST 的分支仍會讀回清單，因此錯誤旁邊的已存報名不會消失。
  4. 送出另一筆合法假資料。成功後網址是 GET 頁面；按重新整理不應再新增。重複按「送出」仍可能產生另一筆，重新導向並非防重送鎖。
if (!ModelState.IsValid)
{
    await LoadRegistrationsAsync();
    return Page();
}
SavedMessage = $"已保存報名，編號 {registration.Id}";
return RedirectToPage();

每一次請用 SSMS 的 TotalCount 比較前後差異。不要為了得到 Id=1 而刪表；自動編號不保證連續。

10. 關閉再開，完成自己的驗收

  1. 記下新增 Id、假姓名、場次與 SSMS 總筆數。關閉瀏覽器並在終端機 Ctrl+C 停止網站。
  2. 重新 dotnet run --launch-profile http；打開同一網址，確認最近 10 筆仍有剛才資料。
  3. 用 SSMS 查同一個 CampusActivityLab09，若網站已多於 10 筆，用自己記下的 Id 在 SQL 加 WHERE Id = 你的數字。
  4. 把姓名改為練習同學，新增一次；交換電腦指出 Input → Registration → Context → SQL Server → 清單的順序。
  5. 填寫 acceptance.txt。若落後可使用 Complete 接回：核對連線、restore、tool restore、database update，再 run；完成版已含 Migration，不再 add InitialCreate。
dotnet restore
dotnet tool restore
dotnet ef database update
dotnet run --launch-profile http

以上四行是 Complete 的接回指令；不是叫已完成的同學重跑新增。網站關閉不會清資料；不要自行刪除資料庫驗收。

先依這個順序找錯誤

找不到專案／dotnet 指令：先 Get-ChildItem *.csproj；確認 .NET 10 SDK 安裝完成，重開終端機。

dotnet ef 找不到／版本不同：在工作專案根目錄 dotnet tool restore；確認 .config/dotnet-tools.json 被複製，工具固定 10.0.15。

編譯找不到 DbContext／UseSqlServer：核對 csproj 的 SqlServer／Design 套件、using 與 Week09Lab namespace，先 dotnet restore、dotnet build。

連線逾時／登入或憑證錯誤：先用同一 Windows 帳號在 SSMS 連同一執行個體；確認服務、帳號權限及本機憑證設定。

Invalid object name／資料表不存在：確認 Lab09、database update 已成功、Tables Refresh；不能只做 migrations add。

Migration 同名／物件已存在：Complete 已附 InitialCreate；用 update。若 Lab09 有手動表或舊結構，停止操作請教師確認，不刪表或套用 Lab08。
