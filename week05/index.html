POINT 01 · GET VS POST

GET 是拿報名頁，
POST 是交出欄位資料。

第一次開啟首頁，瀏覽器向伺服器拿 HTML；填完按下送出，才把 form 內的資料交給後端。

GET／拿頁面

瀏覽器 ── GET / ──→ 伺服器 瀏覽器 ←── 表單 HTML ──

對應 Razor Pages 的 OnGet。

POST／交資料

瀏覽器 ── POST / ─→ 伺服器 名稱、Email、場次

對應今天要完成的 OnPost。

先記「拿」和「交」，不背 HTTP 大全10

POINT 02 · FORM BOUNDARY

form 像一個資料信封，
只有信封裡的欄位會一起送出。

<form method="post"> <label>顯示名稱</label> <input ...> <button type="submit"> 送出報名 </button> </form>

先預測

如果 input 放在 </form> 後面，按下送出時，它會一起送嗎？

</form> <input name="note"> <!-- Form 表單外 -->

先選答案，再用「信封範圍」解釋。

method="post" 描述這次送出的方式11

POINT 03 · LABEL BEFORE STYLE

label 不是裝飾，
它把「問題」和「輸入位置」連起來。

點一下「顯示名稱」，游標也會進入輸入框。

<label for="nameDemo"> 顯示名稱 </label> <input id="nameDemo">
Placeholder 只是範例，輸入後會消失；不能取代 label。
可操作與可理解，先於漂亮12

POINT 04 · FIELD NAME

<label for="displayName">顯示名稱</label> <input id="displayName" name="Input.DisplayName">
labelfor → id

送出名稱name → 後端地址

第三節建立 Input 後，再把這兩行改成 asp-for。

每個停點都必須能編譯；不先引用不存在的屬性13

POINT 05 · PAGE MODEL

小寫 @model 宣告類別；
大寫 Model 是這頁拿到的物件。

// Index.cshtml @model IndexModel @Model.Input.DisplayName // Index.cshtml.cs public class IndexModel : PageModel
  1. @model：宣告這頁搭配哪個後端類別。
  2. IndexModel：在 Index.cshtml.cs 定義的類別。
  3. Model：Razor 執行時實際拿到的 IndexModel 物件。

先記大小寫：@model 是指令，Model 是物件。

兩個檔案透過 @model IndexModel 合作完成一頁16

POINT 06 · INPUT MODEL · STEP BY STEP

RegistrationInput 是資料格式，
還不是這次送來的資料。

public class RegistrationInput { public string DisplayName { get; set; } = string.Empty; public string Email { get; set; } = string.Empty; public string Session { get; set; } = string.Empty; public string? Note { get; set; } }

1. 類別＝空白格式

它規定報名資料有哪四個欄位。

2. 放在正確位置

到 Pages/Index.cshtml.cs，放在 IndexModel 的上方，不要塞進 OnGet。

3. 儲存並確認

建置應為 0 errors；這頁只建立類別，下一頁才建立 Input 物件。

類別描述資料長相；物件才會裝進這一次的值17

POINT 07 · MODEL BINDING · STEP BY STEP

在 IndexModel 裡建立 Input，
準備接住表單 POST 的資料。

// Pages/Index.cshtml.cs 頂端 using Microsoft.AspNetCore.Mvc; public class IndexModel : PageModel { // ① 允許 POST 欄位綁定到 Input [BindProperty] // ② public：框架與頁面程式可存取 // ③ RegistrationInput：型別／資料格式 // ④ Input：IndexModel 裡的屬性名稱 // ⑤ get; set;：允許讀取與寫入 // ⑥ new()：先建立物件，避免 Input 尚未指向物件 public RegistrationInput Input { get; set; } = new(); }

1. 開啟檔案

Pages/Index.cshtml.cs；先確認上一頁的 RegistrationInput 已在 IndexModel 上方。

2. 找到插入位置

找到 public class IndexModel : PageModel，把 Input 屬性加在類別大括號內；不要放進 OnGet。

3. 處理紅線

若 BindProperty 有紅線，在檔案頂端加入 using Microsoft.AspNetCore.Mvc;。

4. Build 自驗

Build 應為 0 errors。畫面暫時沒變是正常的；下一頁才加入 OnPost()。

「小安」實際怎麼走：asp-for="Input.DisplayName" → HTML name="Input.DisplayName" → POST Input.DisplayName=小安 → Model Binding → Input.DisplayName。
完成標準：位置正確、0 errors，並能指出下一頁才處理 OnPost18

POINT 08 · HANDLER · STEP BY STEP

在 IndexModel 裡加入 OnPost()，
接住使用者送出的表單。

public class IndexModel : PageModel { [BindProperty] public RegistrationInput Input { get; set; } = new(); public bool Submitted { get; set; } public void OnPost() { Submitted = true; } }

1. 開啟並定位

開 Pages/Index.cshtml.cs；在 IndexModel 裡、Input 屬性下方加入程式，不要放進 RegistrationInput。

2. 加入完成狀態

Submitted 是布林值；一開始是 false，送出後改成 true。

3. 分清觸發時機

第一次開頁面呼叫 OnGet()；<form method="post"> 送出時，依命名慣例自動呼叫 OnPost()。

4. Build 自驗

Build 應為 0 errors。若還看不到摘要是正常的；第 21 頁才加入讀取 Submitted 的 Razor 區塊。

目前流程：form POST → OnPost() → Submitted = true → Razor 決定顯示摘要。此時尚未驗證內容，空白資料也可能成功。
完成標準：位置正確、0 errors，並能說出 OnGet 與 OnPost 的觸發時機19

POINT 09 · RESPONSE · STEP BY STEP

在 Index.cshtml 加入結果區塊，
讓送出後的「小安」真的出現在畫面上。

@* Pages/Index.cshtml：放在 </form> 下方 *@ @if (Model.Submitted) { <section class="alert alert-success"> <strong>報名資料已收到</strong> <p>參加者：@Model.Input.DisplayName</p> </section> }

1. 開啟並定位

開 Pages/Index.cshtml；找到表單結尾 </form>，把結果區塊貼在它的下方，不是貼進 Index.cshtml.cs。

2. 判斷何時顯示

@if (Model.Submitted) 表示：只有 OnPost() 已把 Submitted 改成 true 才顯示摘要。

3. 讀出姓名

Model 是這頁的 IndexModel；Input 是表單資料屬性；DisplayName 是姓名欄位。

4. 執行自驗

啟動網站，輸入「小安」並送出；送出前沒有摘要，送出後應看到「參加者：小安」。
