HOW TO CLEAR

六個勾，全部亮起來。

  1. 1活動名稱：一個清楚的 h1。
  2. 2任務說明：h2 加上至少兩段自己的 p。
  3. 3冒險裝備：ul 裡至少三個 li。
  4. 4修復連結：找出 herf 的問題，實際點擊。
  5. 5找回圖片：修正檔名，補上有意義的 alt。
  6. BOSS臨時修改：老師抽一題，你當場完成並說明。

完成條件：不是「程式碼看起來差不多」，而是儲存、重新整理、親手操作後確認成功。

先完成共同必做，再挑戰加分任務03

TEACHER DEMO · 20–25 MIN

先看一次完整循環。

1

找到位置

開啟 Pages/Index.cshtml，保留頂端 Razor 指令。

2

小幅修改

只改內容區的一個標題或段落。

3

儲存查看

回到瀏覽器重新整理，觀察畫面變化。

4

故意出錯再修

看錯誤、比對標籤或路徑，修正後再驗證。

安全護欄：不修改 Index.cshtml.cs；不把另一份完整的 html、head、body 貼進 Razor 首頁。
修改 → 儲存 → 重新整理 → 驗證04

MINIMUM TOOLKIT

今天只需要這五組。

h1 / h2　標題

<h1>校園攝影散步</h1> <h2>活動介紹</h2>

p　段落

<p>一起發現校園風景。</p>

ul / li　清單

<ul> <li>手機</li> </ul>

a / img　連結與圖片

<a href="網址">連結文字</a> <img src="路徑" alt="圖片說明">

不必先背完 HTML。需要哪一個，就回來查哪一個。

高階語意與版面設計留到完成主線後05

LEVEL 1 · 找回活動名稱

讓人一眼知道這是什麼活動。

任務

把預設文字改成自己的活動名稱。可以是攝影、美食、夜間散步或社團體驗。

<h1>東海夜間攝影</h1>

驗收

  • 頁面只有一個主標題 h1。
  • 不是「請替活動命名」。
  • 瀏覽器已顯示新名稱。
不要照抄範例，替活動取一個名字06

LEVEL 2 · 發布任務說明

用自己的話，讓同學知道要做什麼。

任務

<h2>活動介紹</h2> <p>第一段：要做什麼。</p> <p>第二段：誰適合參加。</p>

驗收

  • 至少一個 h2。
  • 至少兩個 p。
  • 兩段都是自己的內容。
短而清楚，比寫得很像廣告更重要07

LEVEL 3 · 準備冒險裝備

列出至少三項攜帶物品。

任務

<ul> <li>手機</li> <li>飲用水</li> <li>自己新增一項</li> </ul>

驗收

  • ul 裡至少三個 li。
  • 其中一項不是範例原本提供的。
  • 不是用空白或 br 排成清單。
清單項目沒有名額限制，可以自己增加08

LEVEL 4 · 修復失效連結

網址沒有壞，屬性拼錯了。

故障程式

<a herf="https://gmthu.github.io/aspnet-course/"> 查看課程首頁 </a>

找出問題，做最小修改，不要重寫整段。

驗收

  • 滑鼠可以點開正確頁面。
  • Tab 可以找到連結，Enter 可以開啟。
  • 能說出 href 控制目的地。
畫面沒全壞，不代表 HTML 一定正確09

LEVEL 5 · 找回失蹤圖片

檔案叫 campus-walk，不是 campus_walk。

ASP.NET 路線

<img src="/images/campus_walk.svg" alt="">

檔案放在 wwwroot/images/。

純 HTML 備用路線

<img src="images/campus_walk.svg" alt="">

純 HTML 的路徑前面沒有 /。

修復：改成 campus-walk.svg，並把空白 alt 改成能描述圖片內容的句子。

先查檔名、路徑、大小寫，再猜其他原因10

CHECKPOINT · 自動檢查站

貼上內容區，先做一次自我檢查。

這裡不會修改你的專案，也不會上傳內容。仍要回到自己的 localhost 實際測試連結與圖片。

自動檢查是輔助；最終仍由實際網站與說明驗收11

規則：當場完成、重新整理、說明改了哪個標籤或屬性。不比速度，不需要背答案。
只有老師驗收後，才勾選最後一格12
