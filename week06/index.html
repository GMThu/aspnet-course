MODEL 01 · DATA SHAPE

Model 先不用想得很抽象：
它描述這筆資料有哪些欄位。

不是畫面

HTML 決定使用者看到與操作什麼。

不是資料庫

這次請求的輸入物件不會自動保存；重新開首頁就不保留上次摘要。

是一個結構

屬性名稱與型別，說明這筆輸入長什麼樣子。

本週的 Model 指 RegistrationInput；PageModel 指整個 Razor Page 的後端處理類別。
先分清 Input Model、PageModel 與資料庫05

MODEL 03 · TYPE

型別先回答：這個位置可以放什麼？

string

文字：名稱、Email、場次、備註。

int

整數：未來若加入報名人數，可用數值規則。

bool

是／否：例如是否同意條款；不適合拿來存名稱。

型別不是驗證全部。string 能裝下 abc，但那不代表它是合法 Email。
型別管資料種類；驗證管業務規則07

MODEL 04 · INPUT MODEL · 每行一起讀

這七行，定義一筆輸入的形狀。

1public class RegistrationInput

public：可存取；class：定義型別；名稱是 RegistrationInput。不是資料表，也還沒建立物件。

2{

開始類別內容；下面四個屬性都屬於這個型別。

3 public string DisplayName { get; set; } = string.Empty;

名稱用文字存；get 可讀、set 可寫。初始值是空字串，不代表已經填好。

4 public string Email { get; set; } = string.Empty;

Email 也是文字。命名為 Email 不會檢查格式，後面才加驗證標註。

5 public string Session { get; set; } = string.Empty;

場次存選單送來的 value。本週用文字；空字串代表還沒有選擇。

6 public string? Note { get; set; }

? 允許 null：備註可沒有值。長度限制要另外加規則。

7}

結束這個類別。Input 屬性如何建立物件，接著看第 10 頁。

此段行號從 1 起算；屬性行尾的分號結束宣告 · 圖文版可查完整逐行說明 ↗08

MODEL 05 · HTML 與 TAG HELPERS · 起跑版片段

同一條 Input.DisplayName，連起畫面與後端。

1<form method="post" novalidate>

開始表單；post 送給 OnPost。novalidate 只略過瀏覽器原生攔截。

2 <label asp-for="Input.DisplayName">顯示名稱</label>

標籤文字給人看；asp-for 產生對應輸入框的 for，點標籤能聚焦。

3 <input asp-for="Input.DisplayName">

產生 name、id 與目前值。POST 依 Input.DisplayName 找到同名屬性；input 不需結束標籤。

4 <button type="submit">送出</button>

submit 按鈕送出所在表單。這不等於通過驗證，要由後端判斷。

5</form>

表單結束；輸入框與送出按鈕放在這個範圍內，不要巢狀套 form。

概念片段：完整檔案在圖文版；ASP.NET 先處理 asp-*，瀏覽器收到 HTML · 圖文版可查完整逐行說明 ↗09

最多可以多長？

VALIDATION 03 · ONE RULE

不要背整串；
逐條問它在防什麼。

[Required]

有沒有填？空白不能通過。

[EmailAddress]

有填時檢查格式；不保證信箱存在或可收信。

[StringLength(20)]

文字長度是否超過上限？

[Display] 改善顯示名稱，本身不是「擋資料」的驗證規則。
一條規則配一條可重現測試15

VALIDATION 04 · VALIDATION GATE

先問 ModelState.IsValid，
通過才打開成功區。

public void OnPost() { if (!ModelState.IsValid) { return; } Submitted = true; }
規則未通過return 結束 OnPost，再呈現原頁
全部通過顯示成功摘要

如果先設定 Submitted，再檢查 ModelState，空白資料也可能出現成功訊息。

本例 OnPost 回傳 void：用 return;，不是 return Page();16

TWO LAYERS · 不要把瀏覽器提醒當成 C# 結果

瀏覽器先提醒，與後端擋下，
是兩件不同的事。

前端：送出之前

瀏覽器原生驗證、jQuery 驗證可能先擋住表單；因此 OnPost 不一定收到這次請求。

後端：收到請求之後

Binding → DataAnnotations → OnPost 檢查 ModelState → Razor 顯示錯誤或摘要。

<form method="post" novalidate>
起跑包已加 novalidate，且不載入 _ValidationScriptsPartial；第 02 步起即可觀察後端。後端規則仍保留。
停點：空白資料可以送到後端，但必須被 ModelState 擋下。17

VALIDATION 05 · HTML / RAZOR · 每行的責任

欄位負責輸入，span 負責顯示錯誤。

1<label asp-for="Input.Email">Email</label>

建立對應 Email 欄位的標籤；同一條路徑才能指向正確輸入框。

2<input asp-for="Input.Email"

開始輸入框，指定繫結路徑；本行尚未用 > 結束標籤。

3 class="form-control">

接續上一行。class 是 Bootstrap 樣式，不是 C# 類別，也不是驗證規則。

4<span asp-validation-for="Input.Email"

指定此處顯示 Input.Email 的錯誤；路徑要與輸入框一致。

5 class="text-danger"></span>

紅字樣式；無錯誤時 span 留空。後端驗證失敗時才填入錯誤訊息。

保留起跑包 novalidate，不載入前端驗證腳本；輸入 abc 後應顯示 Email 格式不正確 · 圖文版可查完整逐行說明 ↗18
