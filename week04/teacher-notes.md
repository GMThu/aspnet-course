# 第四週教師授課小抄

## 課程目標

學生不必背完整 CSS 或 Bootstrap。完成後應能：

1. 看懂一條 CSS 的選擇器、屬性和值。
2. 確認 ASP.NET 範本如何載入 Bootstrap。
3. 使用少量 Bootstrap class 完成卡片、圖片與按鈕。
4. 用 `site.css` 加入至少兩項個人化設計。
5. 在瀏覽器實際驗證，而不是只看程式碼。
6. 用六要素提示詞請 AI 提出小步修改，並能說明採用／拒絕與驗證結果。

## 三節課建議節奏

每一節都採「短講解 → 學生實作 → 快速驗收」，不要先把整份簡報講完。

### 上課前先展示預期成品（約 3 分鐘）

- 第 2 頁先按「開啟完整 Demo」，展示桌機版，再切到 390px 手機版。
- 請學生只觀察六項：主色、卡片、圖片、按鈕、兩項個人化、390px 不橫向捲動。
- 明確說明「配色可以不同，不必一模一樣」；Demo 是視覺與驗收參考，不是讓學生覆蓋起始檔。
- 三張實作頁都有「查看預期成品 Demo」入口，學生卡住時可自行對照。

### 第一節｜CSS 改造原理（約 50 分鐘）

- 第 1–3 頁（約 8 分鐘）：故事、預期成品 Demo、過關規則。
- 第 4–6 頁（約 15 分鐘）：示範修改循環、CSS 三段解剖與配色。
- 第 7 頁（約 7 分鐘）：教 AI 提示詞六要素；比較「幫我變漂亮」與可驗收需求。
- 第 8 頁（15 分鐘）：停在「練習一」，學生可請 AI 提供配色候選，再自行選擇與修改。
- 最後 5 分鐘：請 2 位學生指出 selector／property／value，並說明採用或拒絕哪項 AI 建議。

### 第二節｜Bootstrap 加速工具（約 50 分鐘）

- 第 9–11 頁（約 17 分鐘）：確認 Bootstrap 載入位置，示範按鈕與活動卡。
- 第 12 頁（約 8 分鐘）：逐行示範完整 AI 優化提示詞，強調最小片段、限制與驗收。
- 第 13 頁（20 分鐘）：停在「練習二」，學生完成卡片，僅採用一項看得懂的 AI 建議。
- 最後 5 分鐘：抽一位學生拿掉 `btn-primary`，說明畫面差異。

### 第三節｜圖片、個人化與驗收（約 50 分鐘）

- 第 14–16 頁（約 10 分鐘）：間距、響應式圖片與 `site.css` 個人化示範。
- 第 17 頁（約 5 分鐘）：教「讀、比、跑、測、追問」AI 回覆驗證循環。
- 第 18 頁（20 分鐘）：停在「練習三」，學生修圖片、調間距並用實際現象追問 AI。
- 第 19 頁（10 分鐘）：整合檢查；請學生回 localhost 驗證，不把靜態預覽當完整流程。
- 最後 5 分鐘：第 20–22 頁同儕試用、抽 Boss 或記錄下次需補強處；第 23 頁只給提早完成者。

## 常見問題

- **Bootstrap 完全沒有效果**：先檢查 `_Layout.cshtml` 是否載入 CSS、頁面是否使用共同 Layout，再檢查 class 拼字。
- **自己的 CSS 沒有效果**：確認 `site.css` 有載入、選擇器是否正確；也可能被 Bootstrap 規則覆蓋。先用瀏覽器開發者工具看實際套用規則。
- **圖片找不到**：ASP.NET 路線放在 `wwwroot/images/` 並用 `/images/campus-night.svg`；純 HTML 備用路線用 `images/campus-night.svg`。
- **卡片圖片圓角不一致**：優先使用 `card-img-top` 並讓卡片 `overflow: hidden`。
- **學生只會複製 class**：抽題時拿掉或替換單一 class，請他先預測再驗證。
- **AI 一次重寫整頁**：要求學生縮小問題，只貼相關 HTML／CSS，加入「保留 @page/@model、不改 bootstrap.min.css、不要 CDN」。
- **AI 回覆看似正確但畫面壞掉**：先描述實際 viewport、操作與錯誤現象，再要求只修失敗處；沒有 localhost／390px 實測就不算完成。
- **學生貼出敏感資訊**：立即停止；提醒不得把帳密、連線字串、API key、真實個資或整個專案交給 AI。
- **學生照著 Demo 一模一樣複製**：請他改一組自己的主色或按鈕樣式，並說明選擇；Demo 只定義六項完成條件，不限定唯一外觀。

## 快慢分流

- 需要補強：直接使用起始檔，只改主色、按鈕樣式與兩個 TODO。
- 一般主線：完成五關、至少一次 AI 小步優化、同儕試用、Boss。
- 提早完成：亮／暗版本、兩欄 grid 或簡單 transition 三選一。

## 驗收說法

- `ad-hoc green`：只代表剛才某次操作成功。
- 課堂驗收：首頁可開、圖片可縮、連結可操作、窄畫面可讀；學生能說明 AI 建議、實際修改與驗證證據。
- 不把靜態檢查站通過說成 ASP.NET 完整流程已通過。
